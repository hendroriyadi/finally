<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user keyboard → `POST /api/watchlist` | Free-text input becomes a persisted row and a market-source subscription |
| user click → `DELETE /api/watchlist/{ticker}` | A click becomes a state-changing cross-origin request |
| API error body → rendered error message | Server-derived text is interpolated into user-visible copy |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-14 | Tampering | `AddTickerForm` submitted value | high | mitigate | The client uppercases and caps at 10 characters for usability, but the authoritative control is the server's `normalize_ticker` shape check plus parameterized SQL (Plan 01 `T-01-01`, `T-01-02`). The client never assumes its own validation is sufficient — every rejection path renders the error rather than retrying or bypassing. |
| T-01-15 | Tampering | error-copy interpolation in both components | medium | mitigate | The interpolated `{TICKER}` is the client's own normalized `value.trim().toUpperCase()` or the row's existing ticker, never a string parsed out of a server error body, and it renders as React children so it is escaped. No server-supplied message text is displayed. |
| T-01-16 | Spoofing | state-changing POST and DELETE from another origin | medium | mitigate | The backend's exact-origin CORS allowlist (Plan 01 `T-01-04`) is the enforcing control; requests carry no credentials and no cookie, so there is no ambient authority for a cross-site request to abuse. The app has no auth by design (`REQUIREMENTS.md` Out of Scope), so there is no session to forge. |
| T-01-17 | Denial of Service | rapid repeated submit or delete clicks | medium | mitigate | Both controls set `disabled` for the duration of their in-flight request, so a double-click or held Enter cannot queue duplicate writes. Server-side, the `(user_id, ticker)` unique constraint makes a duplicate insert a 409 rather than a second row, and `MAX_WATCHLIST_SIZE` bounds total growth. |
| T-01-18 | Repudiation | no audit trail of watchlist edits | low | accept | Single-user simulated environment with no auth and no multi-party dispute surface. `watchlist.added_at` records when a ticker joined, which is sufficient at ASVS L1 for this context. |
</threat_model>
