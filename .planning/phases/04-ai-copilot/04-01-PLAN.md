<objective>
Give the app an assistant that can actually spend money. Today `execute_trade()` is reachable only from the trade bar; this plan puts a second caller in front of it — a structured LLM reply — without writing a second trade path, a second validation layer, or a second way to fail.

This is the tracer plan for Phase 4. Task 1 wires one path through every new layer in a single commit: an HTTP request carrying free text, a model reply parsed into a typed object, one trade executed through Phase 2's engine, one snapshot recorded through Phase 3's writer, and a confirmation returned on the wire. Task 2 expands that proven seam with the real LiteLLM client behind it and the parsing suite that proves no model output — however malformed — can reach the user as a 500.

Purpose: the riskiest claim in this phase is not "an LLM can be called," it is "a model's output causes exactly the same validated side effects a human's click causes, and nothing more." That claim is provable on one commit, and it is proved first.
Output: `app/llm/` (schemas, mock, client), `app/routes/chat.py`, the router mount, and two test files.
</objective>

## Wire contract produced by this plan

Plans 04-02, 04-03, and 04-04 consume this shape; it is stable from this commit and the frontend is
built against it.

```jsonc
// POST /api/chat  { "message": "buy 10 AAPL" }  -> 200
{
  "message": "Done — I've made the changes you asked for.",
  "actions": [
    { "kind": "trade", "status": "success", "ticker": "AAPL", "side": "buy",
      "quantity": 10.0, "price": 190.32 },
    { "kind": "trade", "status": "error", "ticker": "TSLA", "side": "sell",
      "error": "Couldn't sell TSLA — you don't own that many shares." },
    { "kind": "watchlist", "status": "success", "ticker": "PYPL", "action": "add" }
  ]
}
```

`actions` is `[]` when the model proposed nothing — that is the ordinary conversational case, not an
error. Absent fields are omitted-or-null rather than zero: a failed trade has no `price` because no
fill happened. `kind: "watchlist"` entries are declared here so the frontend can be built against the
complete shape, and are first *produced* by Plan 04-03.
